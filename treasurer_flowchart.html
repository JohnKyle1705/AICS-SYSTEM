This flowchart maps out the complete lifecycle of a Municipal Treasurer account in the AICS System (Municipality of Daanbantayan, Cebu). It details approved request intake, financial validation, category liquidity gating, Disbursement Voucher (DV) preparation, atomic multi-table synchronization, and COA regulatory reporting.

User Role Municipal Treasurer (profiles.role == 'treasurer')
Database Table(s) requests, funds, payouts, fund_transactions, system_logs
Application Route / API /treasurer, /treasurer/requests, /api/treasury

Phase 1: Approved Queue Intake

  • Role Authentication: Only verified active staff with profiles.role = 'treasurer' have clearance.
  • Intake Gating: Only applications with status = 'Approved' and release_status = 'Pending Release' are queued.
  • Discrepancy Loop: Erroneous records are returned to Admin with remarks via action: 'return_request'.

Phase 2: Budget Liquidity Verification

  • No-Overdraft Rule: System programmatically enforces funds.current_balance >= amount_approved.
  • Category Isolation: Separate fund pools for Medical, Burial, Educational, Food, and Transportation.
  • Replenishment: Treasurers can record new municipal budget appropriations via /treasurer/funds.

Phase 3: Disbursement Voucher (DV)

  • Voucher Tracking: Generates unique voucher identifier (DV-YYYY-XXXX) and assigns check/cash mode.
  • Readiness Elevation: Updates request state to release_status = 'Ready for Release'.
  • In-Person Claim: Physical government ID and payroll signature verified at Municipal Treasury counter.

Phase 4: Atomic Sync & COA Reporting

  • Atomic Release: Deducts current_balance, increments total_released, and inserts payouts entry.
  • Immutable Ledger: Every payout produces a double-entry row in fund_transactions with audit hash.
  • COA Compliance: Exportable liquidation reports in official PDF, Excel (.xlsx), and CSV via /treasurer/reports.
